# Smoke：Cocos Creator 3.8.6 2D 演示项目

> 当前旧包视觉与交互验收基准为 **V1.0.8**；版本目录和合并解包文件的选择规则见 [旧包参考](docs/legacy-reference.md)。

首页 UI 的控件位置、尺寸和响应式布局以旧包 V1.0.8 最终生效代码为依据；参考图片只补充大致区域和构图，不用于测量精确位置。详见 [需求与状态](docs/requirements.md)。

本工程从空白 Cocos Creator 3.8.6 竖屏 2D 工程开始，重新实现一个“首页烟盒 → 抽烟互动 → 本次结果”的演示闭环，并已加入空盒补盒页与广告占位流程。旧微信小程序的编译包只作为行为与画面参考，不能直接导入 Cocos。

新窗口接手时，依次阅读：

1. [需求与状态](docs/requirements.md)：已确定范围、待做、暂缓、验收条件。
2. [模块设计](docs/architecture.md)：场景、脚本职责和依赖。
3. [旧包参考](docs/legacy-reference.md)：证据、素材位置与不能直接复用的部分；进一步看 [逐方法规则](docs/legacy-rules.md)、[全包方法索引](docs/legacy-module-index.md) 和 [新旧差异表](docs/legacy-vs-current.md)。
4. [素材与待确认项](docs/assets-and-decisions.md)：需要用户提供的截图，以及图片、音频替换标记。
5. [四张画面参考](docs/visual-reference.md)：首页、取烟过渡、点火前互动、结果的可见布局与首版取舍。原图保存在 `docs/reference/`。

当前状态：`game.scene` 已挂载运行入口，首页、取烟过渡、互动页和结果页的首轮运行时画面已经实现；空盒补盒页、烟票补盒、2.8 秒主按钮扫光和广告占位流程已编码。首页“戒烟”已接入“今日戒烟”两页签、本机记录、日志和趋势页；“收烟榜”已接入空数据页面与后续数据源接口，接烟事件存档尚未实现。烟票补盒、戒烟记录和排行分组逻辑通过假存储或纯函数测试，页面效果仍待用户在浏览器验收。已临时导入王溪烟盒皮肤及四类音效，并通过 Creator 浏览器首轮闭环验证。旧包静态审计发现数项尚未对齐的业务与 Graphics 规则，见差异表；后续修改和验收应以该表为依据。

启动时由 `GameBootstrap` 通过 `BundleLoader` 加载 `prefabs` Bundle，并行加载 `common/bottom`、`common/side`、`common/top`、`common/smokePack`，全部完成后在 `Canvas` 下实例化为同名直接子节点，再启动页面流程。若场景中已有同名节点则复用。`bottom`、`side`、`top` 接入现有按钮和状态逻辑；`smokePack` 沿用隐藏参考状态，可交互烟盒仍由代码绘制。四个节点保留在 Canvas 下；页面显示和隐藏时同步控制首页 UI。代码与资源加载逻辑已检查，效果由用户验收。

Bundle 目录为 `assets/prefabs`，名称在 `assets/prefabs.meta` 中明确设为 `prefabs`。后续可调用 `BundleLoader.loadPrefab(bundleName, path)` 加载其他预制体；资源路径相对 Bundle 根目录且不带扩展名。加载错误在控制台打印具体 Bundle／预制体路径；加载完成前退出场景不会再创建节点。资源加载回归检查命令：`node tools/test-home-bundle.cjs`。

首页按钮现在共用 `UIButton` 组件，顶部、侧栏、底部导航和主按钮均在各自 `bg` 上接入按下反馈、禁用状态和防连点；点击音效和视觉缩放目标可配置。文字扫光已独立为 `TextSweep`，挂在 `one/Label` 上，读取 Label 的文案与字体设置，以同一张 Canvas 绘制底字和白金／暖金亮带；默认 2.8 秒从左到右循环。`one/icon` 图片隐藏，空盒改为“补一盒”并继续扫光，开盖和取烟期间暂停。组件配置与代码示例见 [通用 UI 组件](docs/ui-components.md)，效果由用户验收。

顶部 `button2～button6` 的点击区域使用各自 `bg` 的 UITransform 尺寸和位置，父节点上的 Button 停用；`button2～5` 分别进入打卡、戒烟、收烟榜和成就，`button6` 仅展示公告，暂无详情跳转。

`top/ts/bg` 使用背景当前 440×89 区域接入按压反馈，点击打开“添加到我的小程序”教程弹层，设置页顶部入口复用。弹层用 Graphics 绘制旧包两步示意，支持遮罩关闭与中间内容滚动；当前浏览器无法核验微信添加状态，领取按钮禁用，不增加烟票。效果由用户验收。

设置入口使用 `top/button1/icon` 的 91×91 点击区及通用按钮按压反馈。设置页暂由 `SettingsController` 用 Graphics/Label 绘制，按旧包 V1.0.8 的 720rpx 内容宽、卡片和设置行布局换算到当前画布，支持纵向滚动与背景色块横向查看。已接入当前运行的音效总开关、本项目存储占用估算及帮助/关于；其他设置项显示未开放状态。视觉效果由用户验收。

侧栏 `side/record`、`record2`、`record3` 同样把 Button 挂到各自 `bg`，使用背景的尺寸和位置检测点击。记录入口累计打卡 3 天开放，已接入“赛博记录”独立页面，包含打卡／抽烟／戒烟／任务／烟票五个页签、统计、烟费估算和明细。新抽烟及烟票变动开始保存真实记录，旧累计数据缺少的明细不补造；任务奖励与部分指标保留接口。实验室累计打卡 2 天开放，已有六分类全屏页面、方案保存／恢复、每日权限预览与抽烟配置联动；换盒侧栏入口仍待接入。范围与限制见 [记录页](docs/records-page.md) 和 [烟雾实验室](docs/smoke-lab.md)，效果由用户验收。

底部导航 `bottom/buttons/Node/bg`、`Node2/bg` 分别检测“来一根／全球”的点击。`DemoFlow` 已通过 `HomeController.setBottomNavigationHandlers` 接入全服主页；首页当前选中项保持本页，全服底部“来一根”返回首页。全服页复用底板与两组导航的副本，按旧包 CSS px 规则用 Graphics 绘制统计、影响入口及商店展示；未接服务器时显示未连接和“—”。数据源与二级入口接口见 [全服主页](docs/world-page.md)，效果由用户验收。

全服页“查看更多”已接入独立商店页，支持七个分类、套装展示与空状态，烟票读取本机打卡余额；返回保留全服页滚动位置。页面沿用 375px 参考宽铺满画布，商品详情、活动分享和收藏数据继续保留接口。效果由用户验收。

打卡成功后的解锁提示已替换为完整弹层：半透明遮罩、金棕渐变卡片、锁链打开动效、逐项功能说明与滚动列表。按累计打卡第 1／2／3／4 天触发，第 1 天含“去设置开启／稍后再说”，其他天为“知道了”；从弹层进入设置后返回打卡页。功能本身尚未接入的部分仍见差异表。已编码，画面效果由用户验收。

## 修改与文档同步约定

实验室当前优先完善 UI：`InitialSettings.ENABLE_SMOKE_LAB_UI_PREVIEW = true` 时普通颜色、吐雾方式、烟量和基础形状可直接点选，保存和恢复只保留本次运行的预览状态；实际烟雾效果留在 `SmokeLabUIHooks` 接口，尚未绑定这些预览回调。颜色卡片已改为圆色点、独立圆勾、选中渐变和窄屏单列。完整范围见 [烟雾实验室](docs/smoke-lab.md)，画面由用户验收。

初始参数统一位于 [InitialSettings.ts](assets/scripts/config/InitialSettings.ts)，无需挂载场景。已接入独立的打卡累计／连续天数、烟票余额、今日打卡状态、剩余支数、盒盖状态、累计抽烟数、默认音效与音量、应用调试日志及广告预览开关。默认烟盒仅支持王溪，戒烟初始天数为预留参数，完整状态、限制及查看弹层的配置示例见 [初始设置](docs/initial-settings.md)。当前重置开启，累计／连续／烟票均为 2，今天未打卡；重新运行后打卡可查看第 3 天解锁弹层。初始存档参数仅在重置开启时应用，默认偏好和开发预览开关每次启动读取；查看后将重置开关改回 `false`。

- 每次修改代码后，完成前必须检查相关 Markdown 是否仍与代码、当前需求和旧包差异一致；不一致时，同一轮同步修改 `docs/requirements.md`、`docs/legacy-rules.md`、`docs/legacy-vs-current.md` 等相关文档。若无需改动，也要明确确认已检查。
- 修改 UI 尺寸、运行时 Label 或 EditBox 前，先阅读 [UI 易错点与复用约定](docs/ui-pitfalls.md)：同一 UI 组合统一尺寸倍率；输入框配置与 Label 复用须在激活前完成；聚焦／失焦缓冲期间暂停键盘重建，旧输入先隐藏脱离、延迟销毁，并隔离旧事件。这些是后续修改的检查项，不能只修当前页面外观后再次引入。
- 文档要区分“已编码”“已静态验证”“用户已看过效果”“达到旧包等效”；不能把编译通过或已有类似图形写成效果验收通过。
- **2026-10-15 用户明确要求：视觉效果是否成功由用户自己查看和验收，Codex 不主动验证效果。**除非用户后续明确要求，不打开浏览器检查画面，不做截图对比、离屏像素或动画效果模拟来判断视觉效果是否成功。修改后只做必要的编译、代码静态检查和业务逻辑检查；文档记录“已编码，效果由用户验收”，不得把这些检查写成视觉效果验证通过。
