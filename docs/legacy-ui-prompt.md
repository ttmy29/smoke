# 参考旧包实现完整 UI：复用提示词

整理日期：2026-10-16。

整体 UI 包括页面外观、各种状态、点击后的二级页面和返回路径。接口占位应留在业务层，不能用来省略界面。

以下内容可以直接作为后续任务提示词使用。

---

请参考旧包，实现当前模块完整的 UI 和页面交互链路。

## 一、参考依据

旧包目录：`E:\json\wxd0b7dafebccb8110_unpacked`。

以 V1.0.8 为准，先阅读项目 [旧包参考](legacy-reference.md) 的版本选择规则。结合最终生效的模板、样式、组件和业务代码分析，不能只看图片、文件名或某一段 CSS。

## 二、“整体 UI”的范围

整体 UI 包括：

- 当前页面的布局、颜色、字体、尺寸、间距、边框、阴影、图案和绘制层次。
- 选中、锁定、已解锁、空数据、库存、数量、任务进度等状态。
- 所有入口点击后对应的页面、弹层、页签和确认框。
- 二级页面的内部 UI、返回路径及返回后的状态恢复。

例如：点击“散烟盒／进入”，应打开旧包对应的散烟盒界面，并还原其中的 UI 和返回行为。不能只绘制入口，给它留一个空回调就认为完成。

## 三、先梳理再实现

修改前先梳理：

`入口 → 页面 → 按钮／卡片 → 二级页面或弹层 → 返回位置`

逐一核对旧包每个可见控件的作用，避免漏掉页面、按钮、说明、进度或交互状态。

## 四、绘制要求

- 按旧包对应页面模式的实际代码确定比例和位置。
- 可复用当前项目已有组件、材质和绘制方法。
- 不默认把主页控件等比例缩小；目录页、详情页可能有独立尺寸和样式。
- 烟盒等对象要还原完整结构、贴图裁切、品牌文字、盒盖、侧面、厚度和阴影。
- 同一 UI 组合使用统一缩放规则，兼顾窄屏和滚动；修改前阅读 [UI 易错点与复用约定](ui-pitfalls.md)。

## 五、未完成业务的处理

- 保留旧包原本的 UI、文案和按钮。
- 不添加“未开放”“未接入”“开发中”等占位文案或提示弹窗。
- 页面跳转、弹层打开关闭、页签切换属于 UI 范围，应实际实现。
- 广告 SDK、服务器、支付、分享、解锁事务等业务可以保留清晰的回调接口。
- 尚未接入的业务回调可以静默，不得伪装成功、扣款、发奖励或修改解锁状态。

## 六、数据要求

优先读取当前项目已有真实数据，沿用旧包的统计口径。

例如成就进度使用已完成成就数量，连续打卡使用历史最长连续天数。

保留旧包的数量、容量和“当前 / 目标”显示结构；缺少数据时保留接口并使用“—”，不要伪造数值，也不要直接删掉对应区域。

## 七、素材要求

优先使用已导入的旧包素材，核对版本、路径和引用。

缺少素材时先检查旧包是否通过代码绘制、特殊规则隐藏或远程加载，不能随意用其他图代替。

## 八、完成与检查

完成后同步相关文档，说明已完成的页面链路、保留的业务接口及真实差异。

进行必要的编译、业务和生命周期检查。

视觉效果由我自行查看验收，不主动打开浏览器、截图对比或模拟效果，也不能把编译通过表述为 UI 已完全一致。
