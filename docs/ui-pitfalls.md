# UI 开发易错点与复用约定

本文件记录本项目已出现的问题、原因和后续开发检查项。修改 UI 尺寸、运行时 Label 或 EditBox 前应先核对本文件。当前引擎为 Cocos Creator 3.8.6，设计分辨率为 941×1672；以下是代码约定与既有修复记录，不代表已完成手机或画面验收。

## 一、混合单位造成比例失衡

### 已出现的问题与原因

实验室颜色卡片的色点、勾选框、内边距使用 750 布局单位，经 Stage 按 `941 / 750` 整体缩放；名称、说明、卡片最小高度和列间距却使用 `旧包 px × 750 / 实际浏览器 CSS 宽度` 反算。

这样在浏览器预览宽度也为 941px 时，色点直径约为 43 个设计单位，名称仍只有 14 个设计单位。文字、色点和卡片没有按同一倍率变化，出现色点显大、文字显小、卡片偏矮的比例失衡。**941 是游戏设计宽度，不等于旧包的手机 CSS 参考宽度；不能直接拿实际浏览器宽度替代参考构图宽度。**

### 当前颜色区采用的统一换算

旧包手机参考宽度取 375px，同一组合内所有尺寸按这套比例换算：

```text
旧包 CSS px → 750 布局单位：值 × (750 / 375)
旧包 rpx    → 750 布局单位：值保持不变
750 布局单位 → 941 设计单位：由 Stage 统一乘 (941 / 750)

最终：旧包 CSS px × (941 / 375)
```

| 项目 | 旧包手机参考值 | 941 设计宽下的换算值 |
| --- | --- | --- |
| 色点直径（不含外圈） | 34rpx，约17px | 约42.7 |
| 名称字号 | 14px | 约35.1 |
| 说明字号 | 12px | 约30.1 |
| 卡片最小高 | 64px | 约160.6，可随文字撑高 |
| 列间距 | 8px | 约20.1 |
| 勾选框直径 | 28rpx，约14px | 约35.1 |

对应实现为 `assets/scripts/lab/SmokeLabController.ts` 的 `REFERENCE_PX`、`SCALE` 和 `colors()`。完整布局见 [烟雾实验室](smoke-lab.md)。

### 后续尺寸修改必须检查

- 先注明数值来自 CSS px、rpx、节点局部单位还是 Canvas 设计单位；同一张卡片的图形、文字、行高、边框、间距及点击区域应在同一坐标系中布局。
- 同一 UI 组合统一参考宽度和换算入口。不能让图形随画布放大，而文字、高度仍按浏览器固定像素计算。
- 已放在缩放 Stage 下的子节点，只填写局部布局单位，不能再次乘 `941 / 750`；也不要把设备像素比重复计入。
- 实验室颜色区的实际 CSS 宽度仅用于 ≤340px 单列断点；卡片宽度根据列数和可用内容宽计算，字体与最小高继续按参考构图缩放。
- 有明确需求需要固定屏幕像素大小的控件可单独处理，但必须记录例外原因和换算方式。不要把本颜色区的 375px 参考策略直接套到烟雾物理参数或所有模块。
- 动态文本按实际高度撑开，同一行卡片取最大内容高度；不要通过 `SHRINK` 或随意放大某个色点掩盖整体比例问题。
- 从源码核对数值与倍率即可完成静态检查；画面效果由用户验收，编译通过不能写成显示已正确。

## 二、EditBox 的多余 label、文字错位与滚动条

### 已出现的问题与原因

| 现象 | 原因 |
| --- | --- |
| 额外显示默认的 `label`，输入文字重叠 | 在已激活节点上添加 EditBox，组件预加载时自动创建文字节点；随后重新创建另一套 Label 并替换引用，留下未被 EditBox 控制的旧节点。 |
| 文字出现在输入区上方或偏离中心 | 普通 UiFactory Label 默认为中心锚点，而 EditBox 按左上角定位其文字节点；直接沿用普通 Label 的锚点会错位。 |
| 出现原生滚动条、箭头或不一致的输入样式 | DOM 输入类型在预加载时确定；激活后才改输入模式，可能已按默认 ANY 创建多行 textarea。只改画布文字无法消除原生输入框的默认样式。 |

### 新增或修改输入框的顺序

1. 创建输入节点后，先设 `input.active = false`，再添加 EditBox。
2. 在激活前设置正确的 `inputMode`、完成键类型和最大长度。单行金额输入使用 DECIMAL；不要等 DOM 已创建后才从 ANY 改成单行。
3. **注意：inputMode 的 setter 即使在未激活节点上，也可能创建文字节点。**复用 `TEXT_LABEL`、`PLACEHOLDER_LABEL`／组件已有引用，确认缺失才创建，不能无条件添加第二套。
4. 按 EditBox 的定位方式设置两类 Label：锚点 `(0, 1)`，左对齐、垂直居中、不换行、CLAMP；内容大小和定位由输入框同步，不能再套普通居中 Label 的偏移。
5. 文本通过 `edit.string` 写入，占位提示通过 `edit.placeholder` 写入；只改占位 Label.string 会被组件后续同步覆盖。
6. 完成配置和事件绑定后，再激活节点。
7. 网页聚焦事件发生时，先等微任务让引擎完成 DOM 聚焦和样式同步，再检查当前 EditBox 仍有效且处于焦点、`document.activeElement` 是对应的 `.cocosEditBox` 单行 INPUT，然后按需重置 border、outline、padding、margin、background、boxSizing、lineHeight 和尺寸。
8. 当前记录页使用文本 INPUT 配合 `inputMode='decimal'` 和 `enterkeyhint='done'`，避免浏览器数字箭头；金额格式、范围和长度仍由组件及业务校验处理。该网页处理需先判断 document 存在，不能直接用于原生／小游戏输入实现。

## 三、手机键盘重排与 scrollIntoView 空引用

### 报错与触发链

```text
Cannot read properties of null (reading 'scrollIntoView')

输入框聚焦或触摸
→ Creator 3.8.6 安排约 400ms 后滚动输入框的回调
→ 手机键盘弹出，页面可见高度变化
→ 页面按新高度重新 render，销毁原输入框
→ 原输入 DOM 引用已清空
→ 引擎延迟回调仍执行 scrollIntoView，触发空引用
```

快速保存、取消、切换页签或关闭页面也可能在延迟回调结束前销毁输入框。仅防住键盘弹出时的 resize，仍可能漏掉这些退出路径。

### 本项目的修复与后续复用约定

- 输入框聚焦期间暂停“可见高度变化 → 整页重建”；失焦后再保留 500ms 布局缓冲，等键盘退出和引擎延迟回调完成。
- 输入时直接同步草稿和局部错误提示；不要每输入一个字符就清空父节点并重建 EditBox。
- 保存、取消、切换页签、页面关闭等清理路径统一进入输入框退役处理：清除当前引用 → 失焦 → 停用隐藏 → 从旧父节点脱离 → 500ms 后检查节点仍有效再销毁。必须在销毁旧父节点前脱离输入节点，否则会被一起提前销毁。
- 停用／隐藏不能当作“引擎延迟回调已取消”。保留输入框及其 DOM 引用直到回调结束；延迟释放不能依赖已经停用的页面继续 update。
- 当前使用 `setTimeout` 释放退役节点；回调先检查 `isValid`。正常清理应安排最终释放，避免只隐藏后一直保留节点。
- 原输入框可能还有滞后事件，TEXT_CHANGED、EDITING_RETURN 等入口必须核对它仍是当前输入框，避免覆盖或保存新草稿。
- 500ms 是针对当前 Creator 3.8.6 约 400ms 回调留出的缓冲，不是所有引擎版本的通用常量。升级引擎后要重新核对延迟和清理行为；不要仅把时间任意加长，也不要通过改全局 scrollIntoView 或引擎安装目录掩盖销毁顺序问题。

## 实现位置与检查边界

- 记录页参考：`assets/scripts/records/RecordsController.ts` 的价格输入构建、`resize()`、`clear()`、`retirePriceInput()`、`savePrice()` 和 `dismiss()`。这些约定目前是已有实现，尚未抽成通用 EditBox 组件；新页面不能假设添加 EditBox 后会自动具备这些处理。
- 数据／生命周期检查：`node tools/test-records-input.cjs` 覆盖聚焦时暂停重排、400ms 内 DOM 引用存续、500ms 后释放、无关子树清理和旧输入保存事件隔离。该检查不创建浏览器，也不代表手机键盘和显示已验收。
- 输入问题专题见 [记录页](records-page.md)。修改以上代码时，同步本文件与对应专题；文档修改本身无需重新运行应用或验收画面。
